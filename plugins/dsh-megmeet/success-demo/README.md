# DSH 资料库选型与变更复核演示

先用浏览器打开 `index.html`。选择“初次选型”“工况变化”“资料库扩充”。页面只展示已经保存的引擎结果。切换场景不会在浏览器中重新做工程判定。禁用脚本后，三个场景的结论和图表仍完整显示。

## 案例与资料

真实采购背景是中国煤科重庆研究院2025-04-08公告中的SDR-240-24：[采购原文](https://cg.ccteg.cn/cms/channel/ywgg2hw/50378.htm)。负载、尺寸与环境变化为演示工程需求。

- 初次选型：180W持续负载、25℃，需要216W额定连续能力。V1选出SDR-240-24。
- 工况变化：300W持续负载、55℃，需要360W。V1没有通过全部条件的型号。SDR-240的360W峰值限3秒；SDR-480本体过宽。
- 资料库扩充：V2加入PULS官方原件。CP20.241-R2在55℃额定480W、本体48mm，并有DC OK继电器依据。

公共条件为24VDC、176–264VAC、50–60Hz、DIN导轨、本体宽≤65mm、DC OK继电器。安装前提为垂直且输入端子朝下、海拔1000m、上50mm、下40mm、左右各15mm。间距独立于本体宽度。已知机械公差按上界校验。

V1有30个真实型号，V2有39个。11份原件覆盖9个MEAN WELL系列和2个PULS系列。没有复制型号来扩充数量。`materials/facts.json`保留额定参数、逐项引文、PDF页码、图读方法、安装条件以及另列的PowerBoost条件。`download-manifest.json`保留原件哈希、版本和下载日期。原件未改写。

明纬温度降额图由人工视觉核对后读取。把温度和输入降额图组合用于本场景属于工程推断。PULS480W为标称额定条件，不是任意调整电压、任意负载下的实测保证下限。相关限制见 `research.md`。工程师须完成应用批准。

中文采用“借鉴STE的清晰表达原则”：短句、统一术语和明确责任人。ASD-STE100是英文写作标准，本演示不声明中文正式合规。

## 四组对比

四组均使用同一模型、用户Prompt、资料快照和中文报告要求。A使用通用文件和PowerShell工具；B增加正式DSH Skill；C增加原生业务工具；D使用正式Skill调用同一校验引擎CLI。通用工具对四组均开放。

每组3次完整流程。每次初次选型新建会话，后两步续接自己的会话。当前步骤全部结束后才更新共享资料库。原实验每个步骤相同重复的四组并行。D默认候选上限50与插件3不同，对齐为3后单独补跑，主比较采用A/B/C原记录与D补跑记录。原D记录全部保留。计时和缓存受账户服务负载影响。3次观察不是统计结论。Token来自provider实际用量，包含缓存读取，不换算金额。结果和能力交叉见 [实测观察](comparison-findings.md)。

`records/latest.json`定位正式实验。每个工作流程保留终末回答、完整当轮聊天、原始事件、完整工具调用结果、版本与哈希、模型配置、耗时及Token。`config-difference.json`核验配置差异仅为Skill注册和原生插件接入。`assessment.json`保留自动定位与人工复核结果。失败记录保留。

`records/setup-failures.json`记录正式运行前遇到的DSH Windows环境故障和配置试运行。它们不作为正式的三次重复。没有启用无沙箱模型执行。用户批准的目录权限修复由DSH官方脚本完成，范围限于 `success-demo/workspaces`；备份与回滚命令保存在 `permission-recovery`。演示子进程使用Windows默认临时目录。沙箱仍限制工作区写入。

## 插件与报告

插件版本0.2.0，兼容DSH v0.2.0-rc.2。保留原有五个工具，新增 `megmeet_export_report`。每次调用重新读取并校验管理员配置的目录索引与原件哈希，不需为资料更新重启插件。

查询返回 `catalogRevision`。导出必须传回该值。资料变化后旧查询不能直接生成交付报告，需重新校验。报告目录由管理员配置，模型不能提交输出路径。历史报告使用随机报告号与不可覆盖文件，包含当轮资料库快照。JSON驱动Markdown摘要和HTML。可复核历史报告时，使用其中的 `catalogSnapshot` 与 `requestText`，并核对原件哈希。

原生聊天中的资料版本链接使用DSH可识别的绝对路径，例如 `[SDR-240 · 2025-02-17](D:/VisualBoard/dsh-megmeet/success-demo/materials/SDR-240.pdf)`。单击版本可打开对应PDF；页码在核对行中显示。HTML中链接使用相对路径和PDF页码片段，便于浏览器打开与目录搬移。

安装桌面版插件：在本目录运行 `./install-desktop.ps1`。脚本使用已安装桌面版的官方CLI，仅更新本插件与其配置，并保存原profile配置备份。重新打开桌面应用可确保加载新包。公共资料与插件一起保留在此目录，不需要云端业务API。

## 复现

解压后可直接用浏览器打开 `success-demo/index.html`。复现程序前，在项目根目录运行 `./success-demo/setup-runtime.ps1` 安装项目依赖、DSH rc.2运行时与Python验证依赖。再运行 `./success-demo/reproduce.ps1`，重建资料索引、三个确定性场景、交互页并运行测试。使用 `-RunModels` 再做新的四组真实模型实验。需要本机已登录DSH账号、Node≥22.19与Edge。新模型实验的自动定位结果仍需重新人工复核；本次手工注释只适用于已归档的主比较。

搬移目录后，先复现确定性场景，再安装桌面插件以更新管理员路径。旧报告保存原始路径和快照；`node success-demo/scripts/replay-report.mjs <报告JSON>` 可在原路径不存在时，从随附materials目录读取同名原件，并再次核对SHA256。

复现模型实验会切换演示专用 `catalog.active.json`，最终停留在V2。已有实验与历史报告保留。`run-benchmark.mjs`不自动修复Windows权限；遇到沙箱故障应先按DSH官方诊断流程取得目录修复授权。`DSH_DEMO_REPAIR=1`仅用于已取得授权的演示目录修复。

直接Prompt适合少量、偶发且人工复核充分的资料问答。Skill复用流程，也能读文件、执行程序。Plugin提供原生参数接口、受约束业务调用、统一配置及报告记录。Skill＋CLI可获得相同引擎准确性。Plugin＋Skill适合同时需要业务能力和统一使用流程的场景。选择应按接口与运维需要，不能据此宣称Skill不能计算。

本期没有分用户资料权限、向量数据库、云端业务API、价格、库存或交期。

## 已完成的验收

42项测试通过。22份引擎历史报告按原快照重放通过。11份官方PDF哈希一致。桌面安装包与交付代码相同。DSH真实聊天中的厂家版本链接能打开PDF；HTML静态预览完整显示结论和图表。浏览器中的场景、矩阵与36个主比较回答切换已验证，含390px手机布局。

主比较保留36步，另保留原D组9步和5次环境配置试运行。权限回滚备份留在本机 `permission-recovery`，不放入分享压缩包。重新打开桌面应用加载新插件。
