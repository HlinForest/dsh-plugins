# 从原始证据复原工程

0.4.0 增加“工程复原”入口与 `engineering_restore` 工具。它管理输入、提供原记录查询、运行独立核验、记录空目录重放和工程师意见。转换代码由本次 Harness 会话生成；插件不包含 MD50PG、R5 或 R6 的复原答案。

## 每一步的输入与产出

| 阶段 | 用户或工程师提供 | 自动读取或提取 | 输出与进入下一步的条件 |
|---|---|---|---|
| 确认对象 | 原生工程、版本、有效装配变体、任务范围 | 文件清单、大小、哈希 | 原始文件身份确定；未经确认的版本不得自动替换 |
| 冻结证据 | `harness-native-input/1` 清单 | 白名单文件复制、逐文件哈希核对 | 独立只读使用的输入快照；路径逃逸、重复文件、哈希变化、旧复原脚本被拒绝 |
| 器件资料 | 准确型号、封装、位号和用户 PDF | 复用读手册的全文索引、页码、引用与参数草稿 | 绑定保持待工程师复核；不靠规格书替换原设计值 |
| 原理图 | 原始符号图元、引脚、连接、NC、参数、页面记录 | 按位号查询完整原记录及电气连接端点 | 模型生成工程；逐引脚、参数、导线和部分图形检查，差异明确失败 |
| BOM | 逐位号属性、封装、装配状态、物料编号 | 与当前工程一起留档 | 采购身份或变体缺失时只能是草稿 |
| PCB | 原始板框、层叠、规则、布局布线、铜区、机械图形和模型 | 与独立官方导入结果比较部分几何，执行 DRC | 对导入器不能证明的原生语义保持待确认；不能为消除 DRC 修改源设计 |
| 重放 | 本轮新代码、固定输入和工具版本 | 新目录运行，保存命令退出码，比较工程、库、模型及 CSV 哈希 | 非零退出或文件差异不能称为重放成功 |
| 公司评审 | 当前报告、缺项与工程师意见 | 报告与工程哈希绑定、过期检测 | 本地只记录技术演示审阅；不代替公司签核或生产放行 |

原理图检查完成不等于 PCB 完成。公司评审不由模型签字。用户在工作台记录的意见只对应当时的报告；文件变化会使意见失效。

## 当前证据格式

0.5.0 提供 `prepare-native` 本机读取入口：显式指定 `schematic`、`pcb`、可选 `nativeProject` 的绝对路径。复制原文件，在新目录保存所有 OLE 流、原记录、器件/引脚/参数、限定范围的连接重算和嵌入 STEP，然后自动生成下述清单并冻结任务。支持单页平面工程；层级/总线/隐藏引脚等不支持语义会保留诊断并停止创建任务。不会扫描父目录或读取历史案例。读取和安装步骤见 [内网试用](intranet.md)。

支持 Altium 原生文件及 `eda-project-extract` 风格直接提取资料整理成的 `harness-native-input/1`。当前审计器是该格式的适配器，不宣称任意 EDA 格式均可使用。

`manifest.json` 的 `files` 每项需要 `path`、`bytes`、`sha256`；可以附加 `sourceBundle`、`sourcePath`。允许目录为 `00_native/`、`02_extracted/native_schematic/`、`02_extracted/native_pcb/`、`04_assets/native_models/`、`04_assets/native_fonts/`、`05_datasheets/`。只有清单中列出的文件会进入快照。即使放在这些目录中，旧 KiCad 工程和可执行复原脚本也会被拒绝。

原理图当前必要提取项：`components.json`、`pins.json`、`FileHeader.records.json`、`recomputed_connectivity.json`。需要同一原工程的 SchDoc 和 PcbDoc。单纯 PDF、图片、BOM 或规格书不能满足原工程 1:1 复原输入条件。

`inspect` 无位号时返回清点摘要；有位号时返回器件参数、原始图元、引脚原记录和电气端点。原始引脚 Location 可能是符号侧锚点，不能直接当作导线连接点。坐标单位、轴向和端点语义会随结果返回。

## 运行配置与调用

完整工作台增加绝对路径配置 `kicadPython`，需能导入 `pcbnew`、`sexpdata`、`wx`。`kicadCli`、`workspaceRoot`、`workDirectory` 延续已有配置。PDF 读取沿用 `engineeringPython`。本次实际环境为 KiCad 10.0.6；其他版本需单独验证。

无界面 Harness 可只加载 `dsh-engineering-workbench/restoration`，它只依赖 `tools` 服务。完整工作台同时提供界面与规格书任务绑定。工具参数是单个 `request` JSON 文本：

```json
{"action":"create","manifest":"D:/example/input/manifest.json"}
```

其他操作：`preflight`、`list`、`open(runId)`、`inspect(runId,reference?)`、`verify(runId,project,stage)`、`replay(runId,entry)`、`bind-datasheet(runId,taskId,mpn,package,references)`。`stage` 为 `schematic` 或 `full`；重放入口为接受 `--input` 和 `--output` 的 Python 脚本。

正式生成前，除插件环境预检外，Harness 必须在自身沙箱实际写读一个测试文件。主进程可以运行工具，不代表 PowerShell 沙箱 ACL 已就绪。Windows 工作目录宜使用短路径；KiCad 的部分导出仍可能受路径长度影响。权限修复只针对本次工作目录，由运行控制层留痕，不由插件自动扩大权限。

## 核验范围与限制

核验器独立读取模型输出，不使用模型生成的自检结论作为通过依据。覆盖输入哈希、器件与参数、部分别名回映射、逐引脚定义与端点、连接分组和网络名、NC、导线路径、连接点、可见图形文字内容、PCB 位置/焊盘/布线/铜区部分几何、板级图元及模型文件依赖。运行 ERC、DRC 并保存退出码、原始报告和预览。旧式铜区警告输出到日志，避免无界面审计被弹窗阻塞。

0.4.4 的交付复核补充库表失效路径、封装文件可解析性、原理图封装分配丢失和逐封装模型引用数量检查。它们来自真实复原结果中的缺陷。模型第二轮生成阶段使用此前的检查器；最终成品再由这些新增检查复核，不能将补充后的验收结果冒充模型当时已通过的结果。

修复轮增加了直接读取原记录的符号轮廓检查、圆角/圆弧形状检查、文字重复与锚点检查、参数隐藏状态检查、页面越界检查、有效唯一对象标识检查，以及通过原生 UniqueID 核对 PCB 到原理图的关联。曲线按不超过 1° 间隔采样，以双向点到线段距离比较，容差 0.01 mm；这是注明容差的几何近似，不能声称曲线数学定义完全一致。符号库除了路径有效，还必须能解析并包含所分配的符号。工程哈希包含局部页框和字体文件。

另外核对原生字体名称、旋转和粗斜体、引脚名字/编号显示、本地封装中的焊盘定义和图形数量。模型检查从 ComponentBodies6 二进制记录取得所属器件，按 MODELID 对应 STEP 哈希，核对每个实例的 XY 位置（0.0001 mm 容差）；缩放/偏移/旋转另与独立官方导入对照。重复模型实例不能当作无用空引用删除，也不能只补齐数量。每份新报告保存该次核验器代码和 SHA-256，便于追溯检查标准。

检查仍不能证明完整字形、文字占用范围、绝对页框、颜色与填充、所有 Altium 规则语义、STEP 模型实体及所有嵌入依赖均一致。规则检查只拦截配置完全遗漏，不能代替逐项规则映射评审。PCB 官方导入器比较也不能独立证明该导入器没有损失。缺少原 Altium 编译网表、原始 PDF、原 BOM、企业库与原板报告时，总结保持 `PARTIAL`；已知差异为 `FAIL`，不混为缺证据。`completeOneToOneVerified` 当前始终为 false。

0.4.7 将 TTC 字体集合、`design_rule_mapping.json` 和 `font*.json` 字体证据纳入工程哈希与重放范围。这些文件变化后，旧检查和工程师审阅标为过期；不能在评审后修改未等价规则或字体回退说明却继续沿用旧结论。

重放结果的比对范围是工程、局部库、模型、规则、CSV；不比较日志和时间戳。它证明这批脚本可重放，不证明模型下一次随机生成相同代码，也不证明跨 KiCad 版本一致。源码、工具版本、提示词、会话和人工介入记录需由实验控制层一同归档。

规格书绑定目前复用既有阅读结果，保留 PDF 页码、原文、来源哈希和待复核状态；不执行采购选型、不自动修改原工程。缺项清单提供具体获取方法，但资料到齐后的正式公司验收仍需工程师处理。

## 维护者验证

运行 `npm test` 检查工作台与输入/重放约束；使用具备 `sexpdata` 的 KiCad Python 执行 `test/restoration-python-suite.py`，检查独立核验的负例与正例。测试包括空符号体、误显示隐藏字段、重复文字、直角代替圆角、整圆代替有缺口圆弧、过小页面、错误字体旋转、非法/重复 UUID、错误关联路径以及同数量模型使用错误 STEP 文件等。真实工程仍需执行完整 audit 和空目录重放，单元测试不代替交付核验。
