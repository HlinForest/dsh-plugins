# dsh-eda-flow 0.1.0

独立的原理图与 PCB 分步流程插件。安装后从 Harness 侧边栏打开 **原理图与 PCB 流程**，无需安装工程工作台或其他业务插件。

工程师输入 → 默认/AI/自定义处理输出 → 本机工具实际执行 → 查看本次结果 → 工程师确认。

**R6 默认方案会从原始 SchDoc/PcbDoc 重新生成工程。加载方案只预填资料和处理步骤，不会显示历史成品为本次结果。整个默认流程的模型请求数为 0。**

## 使用

优先使用完整内网 ZIP，参见 [安装说明](docs/intranet.md)。环境为 Windows x64、Harness 0.2.0-rc.2、KiCad 10.0.6，首版仅输出 KiCad。插件包内置 Node 运行依赖，完整 ZIP 另含原始 R6 案例资料和 Python 离线依赖。

1. 点击“加载 R6 默认方案”。七步均为“尚未执行”。也可以创建空白新设计/复原项目。
2. 查看本步输入、资料获取方法和处理方案；需要时补充文件或修改参数。
3. 点击“执行本步”，等待真实工具生成图纸、数据、预览和检查。
4. 查看缺项与假设；需要继续草稿时勾选明确确认。此操作不等于生产签核。
5. 第七步下载工程 ZIP、运行报告与自动累积的冻结证据包；确认后点击“执行空目录重放”。

修改需求会使全流程失效；改源文件使提取及下游失效；补规格书使器件资料及下游失效。旧文件保留供追溯，界面不会沿用旧通过结论。R6 设计约束或源文件变化时默认方案拒绝继续承诺原版 R6；补充规格书不改变设计身份。

## 阶段与输入

| 步骤 | 工程师提供 | 自动执行与缺项处理 |
|---|---|---|
| 任务与约束 | 目标、有效版本、板层、贴片/插件、板框、规则要求 | 保存设计依据；未填写不擅自选择两层板/通孔器件 |
| 原始资料与提取 | 复原用 SchDoc/PcbDoc，可选 PrjPcb；新设计用需求说明 | 提取记录、引脚、连接、模型；用 KiCad 官方导入器实际导入原板 |
| 器件与规格书 | PDF、准确型号、位号与封装绑定、企业物料属性 | 提取逐页文字与页码、原始参数和文件哈希；规格确认仍需工程师复核 |
| 原理图 | 连接/NC、器件参数、图纸约束和上游结果 | 实际生成原理图、符号库、网表、SVG 和 ERC |
| BOM 与封装 | 原始属性、装配状态、封装映射、采购资料 | 生成逐位号 BOM 与局部封装；采购缺项保持草稿 |
| PCB | 层叠、机械、布局、布线约束和已确认上游 | 生成板、局部模型、关联、正反面和 3D 预览 |
| 核验与交付 | 本轮结果、独立源证据、工程师意见 | 重新检查、打包、记录限制；另一空目录重放并比较设计内容 |

冻结证据包由流程累积生成，工程师无需先编写内部 JSON。规格书首版提供页码文本提取和器件绑定；语义参数分析交给 AI 输出/人工复核，不将 OCR 或提取文字直接视为已确认电气规格。扫描 PDF 没有可提取文字时需另提供文本版或人工录入。

## 默认输出与真实 AI

- 默认方案位于 `cases/r6`，原始资料来自独立案例包；阶段脚本均接收当前输入和输出目录。
- 默认源和 AI 源共享阶段状态、执行、缺项传播、结果登记与确认接口。
- AI 仅在 `allowModelCalls: true` 且工程师执行 AI 阶段时调用 Harness 当前模型。此版本在本机仅用模拟响应检验接口，未验证真实 AI 生成能力。
- AI 返回单阶段可重放 Python 方案；使用 `request.inputs/dependencies/output/cli`，不得依赖上次目录。运行失败留档，不自动付费重试。对生成物另用宿主工具导出/检查，模型的“成功”文本不能代替检查。
- 运行代码具有 Harness 本机账户权限；首版不是 Python 安全沙箱。原文件先复制成输入快照，下游会校验源文件与上游结果是否变化。
- 空目录重放执行已记录方案，不重新请求模型。脚本硬编码旧运行目录会被拒绝；无法读取依赖时报告重放失败。

## R6 验收边界

复现 R6 与原生完整 1:1 分开记录。R6 包含历史约定的 82.47 × 57.51 mm、R3 板框，字体调整、电源符号处理和规则转换限制；原始轮廓/36 项规则保留为参考。

检查逐引脚网络与 NC、原始参数、坐标与旋转、焊盘铜形状、走线/铜区、模型文件与变换、封装和原理图关联。内容比较保留真实几何、属性、数量和连接变化；忽略随机 UUID、无语义对象顺序、无名辅助封装编号及 CSV 行顺序，同时单独校验对象关联。

缺原 Altium 编译网表、原始页面 PDF、独立排版签核及公司评审；不能宣称完整 1:1、适配实物外壳或可投产。ERC/DRC 有原版保留告警，不能用“零错误”代替一致性验收。

## 开发与本地运行

```powershell
npm ci --ignore-scripts
npm test
npm run check
# 使用 KiCad 自带 Python
& 'C:/Program Files/KiCad/10.0/bin/python.exe' test/content_test.py
node scripts/serve.mjs local-config.json
```

独立本机服务只监听 127.0.0.1，强制关闭模型调用。配置例子见 [安装说明](docs/intranet.md)。自动默认流程验收：

```powershell
node scripts/validate-default.mjs local-config.json validation.json
```

此命令创建两个新目录，记录“自动技术草稿确认”，不能替代工程师签核。现场演示应在界面逐步查看和确认。

## 接口

独立接口 `/api/eda-flow/bootstrap`、`page`、`action`、`asset`；工具 `eda_flow` 的 `request` 参数接受 JSON，支持 `list/create/open/update/files`。页面还支持 `execute/confirm/cancel/replay`，确认与执行必须由工程师触发，模型不能递归启动自身或代签。

数据保存在配置目录的 `projects/<id>/`：原始快照、每次阶段执行的新子目录、版本和脚本哈希、处理输出、工具命令、错误、文件清单、缺项与确认。第七步提供 `frozen-evidence.zip`；绝对路径仅为当次来源记录，重放通过新的输入和输出目录执行。

独立原生提取器首版支持单页、平面 Altium 工程；层级页、总线、无法确认的隐藏引脚语义等不能自动宣称完整提取。失败记录会提示从 Altium 获取编译网表、PDF、BOM、层叠/规则的具体补充途径。
