# 候选局部修改与恢复

第三步可以通过 `design_amend` 修改本次执行已有的模型候选。它由宿主合成完整电路后重新执行全部资料、引脚、网络、用途、计算及原生资源审查；不直接编辑已冻结的原理图，也不自动确认。

`candidateId` 仅在当前执行内有效，来自 `design_resume`、`design_review` 或 `design_amend`。通过全部检查后另行返回 `reviewedDesignId`，只有后者能用于完成当前方案。未通过检查的草稿也可有 candidateId，不能据此跳过审查。

支持的局部操作：

- `movePins`：逐端点提供已有的 `node`、`from` 和 `to`。原网络必须匹配，目标网络必须存在，每个端点在本批只能移动一次；不能移动 NC 或产生空网络。
- `replaceRecords`：按 `section` 和身份 `key` 替换一条现有器件、外围、工作点、应用决策或功能记录。组件身份、符号库及引脚定义不能借此改变。
- `unresolved`：用精确原文增删过时或新增的未定项；完整审查会重新加入仍然成立的来源缺项和计算假设。

新增器件、网络或改变引脚定义时仍需完整 `design_review`。批量改动先作用于副本，失败不改变基础候选。没有板级坐标、历史 CAD 或参考逐脚表输入。

失败执行的最后模型草稿可在输入、附件、已确认资料与回答均未改变时恢复；恢复记录校验上下文和内容指纹，再重新评审。它不继承历史通过状态，损坏的最新记录不能悄悄退回旧版本。

实际流程曾因仅修改上拉接点而重写约 2.7 万字电路，连续三次输出无效 JSON。局部修改接口使模型可只移动端点、更新相关外围依据及储能范围；用户仍通过通用文字和外置 PDF 输入，不承担逐脚编写工作。
