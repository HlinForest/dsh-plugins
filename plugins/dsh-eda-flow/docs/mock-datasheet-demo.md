# 显示板：自然语言 + 模拟 PDF 提取

新建项目选择“显示板演示 · 自然语言 + 模拟 PDF 提取”。API 调用 `create` 并提供 `caseId: display-board` 时也默认采用此模式；历史输入和文件保留，过时模拟资料的确认会失效并给出原因；显式 `reconstruction` 和 `fixed-redesign` 仍保留。

演示只模拟资料提取。每步的“工程师说了什么”“资料提供了什么”“系统生成了什么”分别展示输入、模拟摘录和本次结果。资料名称带模拟标记，所有页码均为演示占位。无需上传 AD、旧网表或手工填写坐标。0.9.3 起也可上传真实 PDF 补充资料，按页提取正文，与预置模拟摘录分别标记。

1. 核对自然语言任务书并人工确认。
2. 整理模拟资料，核对设计需求并确认。
3. 形成器件、引脚、连接与功能检查清单并确认。
4. 工程师确认第三步后，宿主冻结电路与符号；模型通过 layout_inspect / layout_generate / layout_verify 受控排版，独立检查图纸、网表和 ERC。第四步禁止直接改符号、连接或 NC。
5. 从生成工程导出 BOM，核对规格、DNP 与封装。未建专用 PCB 封装仍列入采购 BOM，并保留待完成说明。
6. PCB 显示本轮未执行。
7. 核验、导出工程及证据包；真实模型全流程验收和生产放行状态仍独立记录。

模拟记录包含 id、document、page、pageIsPlaceholder、content、binding、stages、simulated、sourceType。器件记录另含 reference、value、objectRole、originalFootprint、materialCode、materialDescription、assemblyType、装配标志和 pins（编号、名称、电气类型）。有指定外观的记录提供 symbolId 与 appearance：外框、笔画、引脚方向和器件局部尺寸等可见资料事实；不包含旧 CAD 序列化对象、整页坐标或冻结网表。后续真实提取可沿用文档、页码、正文、绑定结构，不能把现有模拟数据的标志直接改成真实验证通过。

输入修改会使相关下游结果失效。模拟摘录固定，修改要求可通过本步自然语言补充；模型应显式处理与资料的冲突。交付包的 text-input.json 与 frozen-evidence.json 保留模拟来源及输入版本。

本套 R6 模拟资料包含 29 个电气器件、85 个引脚和 12 个工艺对象。显示器保留上方主体与向左伸出的下横条、两个连续方形“8”、四个近圆标记及上下各五脚；未确认的图标含义和制造商型号不臆造。全部已指定外观的器件按资料生成 Evidence: 符号，不能用引脚相同的通用符号替代。只有没有指定外观的通用器件才查询本机库。封装几何、实物亮度、红外性能和生产验证不在本轮范围内。

## 0.9.2-beta.3 受控接入

新显示板模拟资料项目默认 controlledLayout=true、layoutEngine=native-kicad。Evidence: 专用符号从项目引脚表及局部尺寸记录实际生成。运行时不读取 AD、旧网表或历史 CAD 模块，也不扫描旧模块目录。查询、快照和冻结保留模拟来源。模拟原理图允许暂缺PCB封装，快照列出deferredFootprints；普通设计仍必须提供封装，不放宽原有流程。

已有 beta.2 模拟项目保留输入、项目身份与历史文件；受控流程升级从第三步失效。缺少完整 R6 器件记录的旧模拟输入从第二步失效，提示新建当前演示，不能静默覆盖工程师编辑或把旧结果当作当前验收依据。受控输出和交付包含 input-provenance.json；不得将模拟来源或测试模型输入称为真实厂家核验。

完整显示板自动验收使用显式测试模型给出电路和排版参数，实际KiCad生成和检查均真实执行。测试设计不打包为演示默认答案；正式生成仍由Harness当前模型处理资料。

受控排版先保留实际电路关系，再处理图面：驱动芯片与串联电阻保持同组并沿引脚水平对齐；红外接收器与滤波、上拉外围保持同组；同网零欧姆器件保留实物及两端网络标签；工艺对象集中。T 形接点输出明确导线顶点和连接点，普通交叉线不自动相连。排版不能通过拆散功能电路或修改引脚来规避检查。

对于已识别的接口并联滤波拓扑，按接口信号脚的实际顺序将电容同排放置，信号水平引出后垂直接入电容，共用回路明确画出。该规则读取当前引脚方向和网络，不使用历史工程坐标。回归直接读取生成原理图，检查七条段电阻支路的连续水平连线，以及三只输入滤波电容的同排与单折弯连线；文字字段使用明确的左对齐起点，避免位号与阻值挤成一串。这些局部检查不替代整页布局的人工质量确认。

整页优先按模型给出的功能组阅读顺序分行，选择可容纳的连续分组并减少总行高，使同一行的组标题对齐。器件和组内电路保持原尺寸；紧凑页面无法成行容纳时保留原有有界搜索。最终采用的组位置写入 page-placement.json，便于区分候选排版与真实输出。标题额外避开图框，不把版面空隙误判为已完成质量验收。

驱动组可以同时包含段电阻与去耦电容。识别到电容跨接当前驱动器 VDD/VCC 与 GND，且引脚方向适合横向排列时，保持七路电阻原有直连，将电容紧凑排列在驱动器上方，并画出真正连接电源脚和地脚的两条电源线。器件位号、网络名称和页面坐标不参与模式识别；不匹配的电路仍使用通用布局。回归检查实际生成图中的电容方向、间距及电源线物理连通性。

红外接收器、RC 滤波与上拉外围也可与接口同组。接口必须含当前接收器的输出、地和供电网络，且引脚均朝向接收电路，才启用该排版：输出与接口输入保持水平直连，电源和地分别走线。接口信号网络与滤波器的电气关系仍由冻结电路和导出网表校验，不把图面分组当成电气依据。原有独立接口滤波组与新同组表达均有真实 KiCad 全流程回归。

检查实际导出的连接分区、器件属性、原始封装说明、装配状态、NC、ERC 和 PDF 碰撞。深层项目目录使用字节一致的短目录副本调用 KiCad，导出记录保存原理图哈希；不改位号来回避路径错误。原显示器的非标准栅格尺寸保留，相关 ERC 警告如实列出，不假报零警告。

工程证据归档同时处理 Windows 长路径：请求、默认资料、依赖工程和输出目录统一使用可访问的绝对路径；ZIP 内仍保留普通相对文件名及原始文件内容，不包含系统长路径前缀。测试覆盖超长目录、中文文件名和归档完整性。工程证据归档与插件发布包是不同步骤，不能据此跳过用户的图纸质量确认。

测试模型全链路、真实 Harness 模型执行、独立基准核对和用户视觉确认是不同证据。模型修正通过自然语言反馈重新执行相应步骤，下游重新生成；测试通过不等于用户已确认图纸质量。用户确认质量前，不发布或同步已安装插件。

显示板演示将 C5/C6/C7 归入 U1 主控组，而不是独立摆在显示器左侧。宿主根据当前冻结资料中的输入脚、对地电容和引脚方向识别输入滤波支路：DIN/CLK/STB 横向接入主控，电容在主控左侧向下分支并共地。该布局与主控上方去耦、七路水平段电阻一起计算边界；显示器独立成组。回归读取生成 CAD 检查三条实际输入连接、连续水平线、相对位置及共地，不使用原工程坐标。

输入滤波的公共地使用独立 SGND 标号连接主控地，禁止为保持整组物理连线而绕主控画大回路。宿主从冻结拓扑识别输入对地电容，只允许这组公共地与主控地通过同名标号连接；三个电容的短地线、主控去耦地线和各条输入信号仍分别核验实际连通。最终 KiCad 导出网表必须证明两段地属于同一预期网络，标签缺失或误名不能通过核验。

显示板默认采用原图功能阅读顺序：上排红外接口、主控，下排零欧跨线、显示器、工艺对象。输入电容和红外滤波电容使用竖向位号/参数字段，保留全部参数并缩短列间距；输入网标放在水平主线左端，电容从线上向下分支。宿主按活动电路角色保留行边界，空间不足时报错，不将辅助器件塞到上排。几何仍从本次生成符号和连通关系计算，不读取原 CAD 页面坐标。

本版将显示器9号和5号引脚的横向连接位置各调整 -0.508 mm，对齐 KiCad 1.27 mm 连接网格；保留其引脚身份、方向、长度及显示器全部外框和内部图形。原始模拟尺寸记录保留，生成器负责连接网格适配，ERC 使用实际检查结果，不关闭网格规则。
