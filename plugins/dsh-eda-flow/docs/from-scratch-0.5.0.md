# 从零设计与原图复原 · 0.5.0 本机试用

新建项目提供从零设计、简短显示板示例、原图复原显示板三种入口。旧项目保持原行为；省略 designMode 的旧 API 调用仍为 reconstruction，新界面默认 new-design。两者沿用 text-mcp 执行，不加载旧工程对象包。

从零流程：简短功能约束 → 第二步 requirements → 第三步 design 清单 → 人工确认 → 实际 KiCad 生成 → 反向一致性检查 → 草稿交付。设计清单包含稳定身份、位号、值、采购型号、符号库来源、封装、装配状态、逐针网络/NC 和按需求归属的连接检查。修改上游会使下游失效。用户无需输入内部 JSON，模型生成清单，界面提供审阅表和补充入口。

design_library 只读查询安装的 KiCad 符号与封装，返回真实引脚、焊盘与文件哈希。默认库目录由 kicadCli 推导为 ../share/kicad；可配置 kicadLibraryRoot。内网不能读取文件时会返回真实工具错误，不剥离保护头、不替换密文或接受新的错误基准。

第三步核对清单结构、需求覆盖及所选库引脚/焊盘；第四步起每次实际 check_export 后，用独立 Python 读取 CAD 状态、KiCad XML 网表、实际导出 BOM 以及封装库。比较器件集合、DesignId、值、MPN、装配标记、引脚、电气类型、网表分组和 NC；执行连接/隔离断言。发现不一致回传模型，最终仍失败则不能完成该步骤。

purchase-bom.csv 从同一清单及已核对的工程逐位号派生，仅纳入 in_bom、on_board 且非 DNP 的器件。实际使用封装以原字节保存到工程 footprints 目录，并写入项目 fp-lib-table。设计清单、库证据、错误与待办、检查报告均留档。

边界：功能断言由模型提出，静态通过不证明需求解释充分；库引脚/焊盘一致不证明厂家电气额定值与机械适配。缺采购型号列为待办，库资料不冒充厂家认证。releaseReady 保持 false；最终只能带待确认项保存草稿。PCB、固件、亮度、时序、温升及实物验证尚未实现。原图复原仍使用原有精准文字任务书，不能用该结果替代从零设计能力验证。

验证：new-design.test.js 覆盖缺需求、重复/漏接引脚、换脚、真实 KiCad CAD/XML/BOM 对照，以及参数、装配、网络、封装的故障注入。browser-new-design.py 验证两种入口、简短输入、保存和旧复原保留。完整测试记录与本机真实试跑保存在 D:/VisualBoard/output/EDA_From_Scratch_20261016。
