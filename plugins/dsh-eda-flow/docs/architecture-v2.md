# 输入驱动的独立流程（历史设计说明）

> 本文记录早期结构化转换模式。0.9.6-beta.1 的新建项目统一走文字设计流程：空白项目与显示板示例只在可编辑文字初值上不同，规格资料由用户上传。下文提及的 `cases/display-board`、固定案例数据与目标摘要已移出发布包，仅保留在测试夹具中。历史项目只读取自身保存的资料；没有自行保存的比较基准时显示缺项，不宣称与旧目标一致。当前操作以 README 为准。

通用服务只处理项目、阶段、资料、模型方案、执行和确认，不依赖工程工作台。显示板的专用转换策略与完整数据在 `cases/display-board/inputs`，确定性转换器在 `python/structured`。

每次新执行都调用 Harness 当前选择的 provider/model。`skills/eda-inputs/SKILL.md` 随模型系统上下文加载，不依赖另一套 Skill 安装器。模型可以分页读取完整输入、PDF 页文字和上游输出，日志记录实际提示词、读取、回复、错误和工具执行。模型选择结构化转换器，或为新设计生成阶段 Python；UI 没有无模型默认执行选项。

结构化转换器沿用已验证本机试验的完整逐对象输入。它不是未知需求自动设计器：与示例不匹配的约束或补充要求会使其不适用，交给模型生成适用程序。首次通用新设计生成能力仍需内网真实模型验证。

原生资料提取器只读取，不调用 Altium 导入器生成整板。TSD 文件返回具体获取方法和缺项。PDF 完整逐页文字保存在本地；模型可按页文件分段读取，扫描图像未做 OCR。

每步有独立目录，保留输入快照、方案、命令、结果和确认。默认输入哈希变化、上游输入变化、输出文件变化都会使相应结果失效。第一版 AI Python 程序以 Harness 账户执行；文件快照与事后哈希检查不是操作系统沙箱。输入哈希和生成器审计不替代公司评审。

显示板核验使用历史目标的语义摘要，解析对象引用关系后比较连接、图形、参数、库和模型；历史完整 CAD 不随插件提供。目标摘要只在最终核验读取。它证明与该目标一致，不证明原 Altium 全部特有语义等价。原始编译网表、原始 PDF、制造层数和通孔金属化仍待确认。

正面预览默认提供清晰阅读图，旁存原始线宽图与原配色图；实际 PCB 线宽不变。工程记录 2 铜层、背面走线，制造单面板不是自动推断项。

重放直接执行已记录模型方案，模型请求为零；它验证执行可复现，不等于第二次模型推理得到相同方案。离线集成测试的模型替身位于 test，未打入安装包，也未计为真实 AI 成功。
