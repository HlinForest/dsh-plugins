# 0.4.0：纯文字 → 模型 → KiCad MCP

新建项目默认使用纯文字流程。显示板默认任务书可以完整查看、编辑、复制和下载；另填的供电、接口、装配、约束、验收、来源、评审和各步公开问答同样进入模型上下文。PDF 附件当前只登记，未读取会明确标注；可粘贴带准确型号、版本、来源和页码的正文继续。

第一步人工确认，第二、三步整理依据和器件信息。第四步由模型从空白工程调用 MCP 创建、读取、修正和检查。第五、七步读取本次生成工程的副本，导出物料和交付结果；原确认结果保留。第六步 PCB 为“本轮未执行”，不会显示完成。修改上游输入后，下游结果与确认失效。

## 发布内容与环境

交付文件是 `dsh-eda-flow-0.4.0.tgz`，包含插件源码、构建后的页面、公开默认文字、通用 MCP 服务以及旧项目兼容代码。它不是 0.3.x 的完整离线安装 ZIP，不含桌面运行时或 Python 离线轮子。此次未替换已安装插件，未重启 Harness。

沿用已安装的 Harness、Node ≥22.19、KiCad 10 和窗口运行时。原有 `workspaceRoot`、`workDirectory`、`kicadCli`、`kicadPython` 配置保留。新增可选的 `mcpPython` 指向 Python 3.10+，需要 `jsonschema>=4.18,<5`；不填写时使用 `kicadPython`。当前网表摘要与归档使用原配置的 Python，仅依赖标准库。

在计划安装的解释器上检查：

```powershell
& '实际Python路径' -c "import sys,jsonschema; print(sys.version); print('jsonschema ready')"
& '实际KiCad CLI路径' --version
```

内网缺少依赖时，由已批准的内网 Python 源或离线轮子安装 `mcp/requirements.txt`。旧 `install-offline-python.ps1` 只对应 0.3.x 离线包，不包含本次新增依赖。配置示例：

```yaml
- id: eda-flow
  config:
    workspaceRoot: 'D:/EDA'
    workDirectory: 'D:/EDA/eda-flow'
    kicadPython: 'D:/KiCad/bin/python.exe'
    kicadCli: 'D:/KiCad/bin/kicad-cli.exe'
    mcpPython: 'D:/EDA/Python/python.exe'
    allowModelCalls: true
```

模型仍由 Harness 选择和管理登录。`allowModelCalls: true` 只是允许工程师点击执行后使用宿主模型，安装本身不发起模型请求。开发验证已禁用真实模型调用。

需要更新现有安装时，先备份对应 profile 的清单、配置和当前插件，再通过 Harness 原有插件管理入口选择本次 TGZ，保留原配置和项目路径。此文不把未实际执行的内网安装标记成验证通过。更新生效后，页面左下角的页面与后台版本应均为 0.4.0。旧项目显示“历史转换工程”，新项目显示“纯文字生成”。

## 模型与工具执行

宿主模型收到完整内联文字，每轮返回一个明确动作：提出问题、调用一个已授权 MCP 工具，或声明当前步骤处理结束。工具结果和错误会返回模型，允许继续修正。宿主沿用工具注册与执行接口；模型无任意脚本入口。

四个通用操作是 `precise_create`、`precise_apply`、`precise_read`、`precise_check_export`，经 stdio MCP 协议执行。工具本身没有显示板模板、旧 CAD 导入、需求解析器或预制调用顺序。模型提供器件、图元、位置和连接参数，KiCad CLI 实际解析工程并导出 PDF、SVG、网表、ERC 和 BOM。

执行令牌限定当前任务目录和允许操作；步骤结束后令牌失效。每步的幂等键单独命名，复制工程不会返回上一步缓存的旧文件路径。第五、七步只允许读取与导出。输入快照、调用参数、返回结果、错误、工程哈希及检查均留档。这些是上下文和应用层约束，不是操作系统沙箱。

KiCad 10 的引脚名称/编号显示需设置符号级可见性。无法实现的逐引脚混合可见性明确拒绝并返回模型。BOM 保留自定义字段、装配状态、引脚数及对象类别，ERC 辅助声明不冒充物理器件。

## 验证范围

本机完成了两次独立 Codex 空白生成，采用同一最终文字输入，与确认过的 AD 基准逐对象核验均为 2,395 项通过、0 差异。这验证指定文字要求和通用工具可以生成该原理图；其中精确连接和坐标由需求明确提供。

插件迁移的本地检查包括真实 Harness 库注册、模拟模型的多轮协议、真实 MCP/KiCad 导出、输入失效、错误修正、目录限制和旧工程兼容。界面检查使用禁止模型调用的本地页面夹具；该夹具的问题是测试状态，不是模型推断。

**Harness 真实模型全流程仍待验证，真实 DSH 模型调用为 0。** Codex 成功、模拟响应和工具测试不能替代该验收。内网没有独立 AD 基准时，第七步的原工程差异显示“未执行”；模型自述不能覆盖真实 ERC 结果。PCB 布局布线、制造和实物性能均未验证。

内网具备模型额度后，应新建空白项目，使用公开文字重新执行，核对模型与 MCP 记录、实际网表成员、NC、器件属性和图纸；再新建第二个项目验证独立再生成。文字模式没有固定调用重放入口。
