# DeepSeek Harness EDA Flow 0.11.3-beta.1 使用说明

本说明对应当前发布包。插件把空白项目和显示板项目放在同一套七步流程中。显示板入口的起始文字会在页面中预填并显示，工程师可以在提交前编辑；空白项目从空字段开始，所有实际存在的步骤输入都可见、可编辑。只有确认后的本步输入才会进入模型处理。规格书正文、隐含连接表和坐标不会藏在显示板预设里。

## 开始前准备

准备 Windows、已初始化的 DeepSeek Harness profile、允许使用的模型、KiCad CLI/Python，以及部署方提供的 TGZ。规格书是项目外部资料，按实际型号准备；内网试跑可以先上传四个大器件的真实规格书。关键器件不需要一次准备整套资料，但型号、引脚和封装相关信息缺失时，流程会保留待确认项。

正常显示板流程不要求预先填写完整的逐脚网表或固定坐标。用户提供功能、供电、接口兼容条件、工作条件和规格书，模型生成候选电路，布局器按拓扑和引脚几何排版。已有 AD 工程只用于独立验收：逐项识别器件、参数、连线与图面差异，区分资料缺失和插件不足；不把完整 AD 网表或历史坐标补进生成输入。四份大器件资料不能唯一确定历史采购组合和工艺标识。

## 安装

在交付包根目录执行 `install\install-intranet.ps1`。TGZ、安装脚本和说明在同一外层目录，不需要访问插件源码；按实际路径替换包文件、Harness CLI 和 KiCad 目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\install\install-intranet.ps1 `
  -SuppliedPackage (Join-Path $PWD 'dsh-eda-flow-0.11.3-beta.1.tgz') `
  -DshPath 'C:\Users\Public\AppData\Local\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd' `
  -Profile desktop `
  -WorkspaceRoot 'D:\EDA' `
  -KicadDirectory 'D:\KiCad\bin'
```

`-WorkDirectory` 默认是 `WorkspaceRoot\eda-flow`。需要指定 Harness 数据根目录时使用 `-DshHomePath`；有批准的 Electron 运行时目录时可以使用 `-DesktopRuntimeSource`。不传 `-Registry` 时，安装器使用本地 pnpm store 和离线模式。安装完成后重启 Harness，并在插件页面确认版本为 `0.11.3-beta.1`。TGZ 不包含 KiCad、Harness 登录信息、模型密钥或外部 PDF。

安装前先按原理图范围运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install\check-environment.ps1 `
  -SchematicOnly `
  -WorkspaceRoot 'D:\EDA' `
  -KicadDirectory 'D:\KiCad\bin'
```

`-SchematicOnly` 仍要求 OR-Tools，因为通用原理图自动布局会调用约束求解器；该参数在当前脚本中只保留为运行范围标签，不免除任何原理图依赖。启用 PCB 前，先对指定 KiCad Python 安装外层 ZIP 中 `offline\wheels` 的离线依赖，再运行不带 `-SchematicOnly` 的完整检查。旧的 `validation/environment-schematic-check.json` 只记录了此前把 OR-Tools 标为可选的历史结果，不能作为当前环境通过证据；请以新的 `validation/environment-contract-*.json` 为准：

```powershell
powershell -ExecutionPolicy Bypass -File .\install\install-offline-python.ps1 `
  -PythonExe 'D:\KiCad\bin\python.exe'
powershell -ExecutionPolicy Bypass -File .\install\check-environment.ps1 `
  -WorkspaceRoot 'D:\EDA' `
  -KicadDirectory 'D:\KiCad\bin'
```

最终外层 ZIP 在 `offline\wheels` 提供 17 个面向 Windows x64/Python 3.11 的离线 wheel；TGZ 本身仍不包含 wheels，Harness 和 KiCad 需要预安装，模型服务需要由内网配置。离线解析验证报告见 [外层 validation/offline-dependencies.json](../../validation/offline-dependencies.json)；本轮只做了 `pip --dry-run --ignore-installed --no-index` 验证，未替用户环境实际升级。当前完整检查若缺少 OR-Tools 会失败，不能把 PCB 环境写成已通过；该脚本不会下载或生成依赖。`install-desktop-runtime.ps1` 仅在需要独立桌面运行时时使用。

## 规格书和工程资料

在第二步添加 PDF/DOCX，在第三步把资料绑定到实际型号或位号。每个关键器件一份规格书通常足够开始，建议至少包含以下信息：

| 信息 | 用途 |
| --- | --- |
| 准确型号、制造商料号和版本 | 区分同系列变体，防止把相近型号当成同一器件 |
| 引脚号、引脚名、方向和电气类型 | 建立命名引脚、功能网和 NC 判断 |
| 供电、逻辑电平、极性、时序或应用条件 | 检查接口兼容性和使用约束 |
| 封装、焊盘号、尺寸和装配限制 | 核对已有库件的 BOM、封装映射和 PCB 约束；缺少精确库件时保留待确认 |

普通电阻、电容和连接器可以在文字约束允许时从本机已核对的通用库选择。关键器件的型号、引脚、封装和机械参数以上传资料为准；资料没有给出的参数会显示为未知或待确认，必须保留来源引用并由工程师核对后才能作为设计输入。

PDF 读取使用页面文字提取。只有整页文字提取结果为空时，页号才会被标记为不可读取；页面只要含有文字，即使同时包含图片，也可能显示为可读取。图片本身（扫描表格、截图、应用电路图）不会从像素中解析，图中的型号、引脚或参数仍需工程师补充可复制正文和来源页码并核对。单个 PDF 还受 50 MB、500 页和总提取文本约 150 万字符的限制。上传成功不等于内容已经提取，页面显示未读取时不要把它当作已确认事实。

### 已有信息、外围和去耦的检查

第二步把带尺寸语义与单位的原文列为覆盖检查项，模型必须保留数值、单位、尺寸含义和逐字引用，遗漏会阻止完成提取。在“提取数据”的“已提取的物理尺寸”表中逐条查看原文；这些尺寸随已确认器件进入后续设计，不能在第三步静默丢失或改值。检查目前覆盖可提取文字中的单位与尺寸语义，不等于读懂所有表格、图片或完整封装。引脚间距、孔径、焊盘直径属于器件事实，不能变成原理图坐标。

第三步对资料识别的红外接收器分别审查供电和输出处理。选择滤波或外部上拉时，检查实际电阻、电容和网络连接；选择省略时需要本器件资料的依据。资料缺少推荐值时，模型可形成写明假设和待验证项的候选；不能将候选值写成厂家推荐值。显示负载的电流控制待定时，不能省掉限流后仍将输出直接或经零欧接到段脚。

每个声明为去耦的电容必须由模型指定服务的器件及供电、返回引脚，并核对两端实际网络。自动布局使用该归属、符号几何和拓扑形成局部组，工程师核对实际图中的位置与连接。全局储能应说明用途，不能为通过检查随意挂到某个器件。归属是功能关系，不是用户逐颗摆放坐标。

## 七步操作

| 步骤 | 页面操作 | 模型处理 | 工程师确认与产物 |
| --- | --- | --- | --- |
| 1. 任务与约束 | 新建“显示板”或“空白项目”，检查并编辑任务、供电、接口、装配、规则和验收文字 | 只保存当前可见输入 | 确认任务边界，形成项目输入 |
| 2. 资料与提取 | 上传关键 PDF/DOCX，或粘贴带来源页码的正文 | 提取来源事实，并生成应用指导；每条事实保留文件和页码 | 检查型号、页码、缺项和应用指导后确认；未读资料不会进入已确认事实 |
| 3. 器件与规格书 | 绑定型号/位号，核对引脚、符号、封装和参数 | 根据需求、来源事实和已确认器件生成完整的 components、nets、NC 和 functions，并进行候选设计复核 | 确认完整器件、网络、NC 和功能；确认后冻结电气设计 |
| 4. 原理图 | 在冻结的电气设计上生成图面 | 首先使用默认自动分组和方向；仅针对实际图面检查缺陷调整分组、旋转、纸张和间距；generic 纸张协议支持 A4/A3/A2/A1/A0 横向，编译器按真实图面 bounds 选择纸张并记录 `effectiveLayout`，不能修改连接、器件、NC 或功能 | 检查实际符号、连接不可变性、布局和可读性；通过图面核验后进入后续阶段 |
| 5. BOM 与封装 | 查看 BOM、料号、符号引脚和封装焊盘映射 | 读取已生成工程的实际库对象和导出结果并进行只读核验；无法确定的封装或料号继续挂起。PDF 文字不会自动创建可制造的自定义 PCB 封装；必须使用本机已核对的库件，或由工程师另行建立并配置后重新确认 | 补齐或确认采购、封装和装配信息 |
| 6. PCB | 明确启用 PCB，填写板框、层数、布线、制造和规则 | 模型按功能/走线关系给出器件顺序，编译器按真实封装逐个排布固定与未固定器件，再由 KiCad/Freerouting 执行布线和 DRC | 检查板框、关键器件、铜层和制造规则；板上器件缺封装时流程会停在待补状态 |
| 7. 核验与交付 | 运行检查并查看交付文件 | 汇总实际 ERC/DRC、BOM、原理图、PCB、PDF 和检查记录 | 工程师复核电气、机械、制造和实物条件；有未解决项时保持待处理状态 |

原理图的公开纸张协议中，`paper` 表示起始纸张。默认情况下，流程根据实际生成图面的 bounds 选择能容纳内容的更大横向纸张，并在结果中记录实际使用的 `effectiveLayout`；A4、A3、A2、A1、A0 都属于支持范围。用户明确固定纸张时，模型必须传 `allowPaperPromotion=false`；内容放不下时返回失败并保留问题，不升级纸张，也不缩小文字或字号强行塞入图面。

阶段 2 的来源事实和应用指导、阶段 3 的完整器件/网络/NC/功能设计都需要人工确认；阶段 3 确认后冻结电气设计，阶段 4 只能在这个冻结结果上做图面布局和核验。上游资料或确认内容改变后重新执行，下游不会继续使用已经过期的阶段输入。

## 排布和连接由谁决定

插件不把显示板器件排布写成固定坐标。电气连接在阶段 3 生成并冻结，阶段 4 只负责原理图图面分组、旋转和编译器布局；PCB 排布使用单独的器件顺序和机械定位输入。排布按以下优先级确定：

| 级别 | 决定因素 | 行为 |
| --- | --- | --- |
| A | 工程师明确且已解析为 `placements` 的固定位号坐标、安装面、旋转和板框 | 作为支持的机械约束执行，无法满足时返回待处理问题 |
| B | 真实封装外形、焊盘、已确认的网络，以及模型给出的器件顺序 | 编译器按顺序保留已放置器件的连接锚点和间距，再安排后续器件 |
| C | 没有固定坐标的器件 | 按 0/90/180/270 度尝试板内位置，排除越界、器件外形重叠和焊盘冲突后选择评分较低的位置 |

PCB 的自动排布是按 `order` 逐个进行的几何打包，不是对全部器件和最终布线做一次全局优化。未固定器件的位置评分会参考已放置器件的电气连接锚点，并对部分飞线交叉增加惩罚；排布完成后才交给 KiCad/Freerouting 布线并运行 DRC。原理图第 4 步首先省略 `groups` 和 `rotations`，由编译器按拓扑识别输入 R-C、驱动输出支路及共享接口，并按真实符号边界和引脚方向布局；只有图面核验发现实际问题后才调整。编译器负责坐标、导线和核验，不能借排版修改已冻结的电气设计。任意禁布区、复杂板形、额外层数等超出当前支持范围的约束必须先提出问题，不能在说明中当作已经强制落实。本轮以达到参考图的组织和连线质量为目标，通过通用布局规则改进，不要求用历史坐标复现图面。

## 显示板试用流程

本轮逐页操作、四份资料替换关系、实际截图和检查结果见 [0.10.0 使用说明与复测流程](../../validation/round-0100/0.10.0使用说明与复测流程.md)。下面保留流程摘要，便于在页面旁边快速对照。

1. 新建项目并选择“显示板”。先阅读每个步骤中已经显示的文字，按实际供电、接口、显示模块和装配要求修改。
2. 在第 2 步上传四个大器件的真实规格书；如果规格书是扫描件，把关键引脚表、封装表和应用条件以可复制文字补到输入中。
3. 运行资料提取，逐条检查来源页码和应用指导。修正错误或补充缺项后确认第 2 步。
4. 在第 3 步绑定实际型号和位号，核对命名引脚、NC、符号、封装和参数。接口电平、极性、时序或连接器映射不明确时，先补齐兼容性选择再确认。
5. 生成完整的 components、nets、NC 和 functions，检查后由工程师确认并冻结电气设计；进入第 4 步只做图面分组、旋转和布局核验，第 5 步只读检查 BOM、封装和焊盘映射。如果启用 PCB，先补齐所有板上器件的实际封装。
6. 在第 6 步显式启用 PCB，输入板框、层数、制造和布线规则，检查自动排布、布线和 DRC。
7. 在第 7 步查看实际检查结果和交付文件，记录仍需工程师处理的电气、机械或制造问题。

## 缺少兼容性信息时

以下信息缺失时，流程会提出待确认问题或保留未知字段：准确 MPN、供电范围、逻辑电平、输入输出方向、极性、时序、接口/连接器针脚映射、封装变体、焊盘编号和安装限制。不要用“同系列”“常见封装”或相近型号替代这些事实。补齐资料并重新确认后，阶段 3 才能把它作为设计输入；PCB 已启用时，板上器件没有封装会直接阻止候选设计通过。

## 验证记录

实际 Harness 重跑结果、输入资料和待处理项见交付包外层 validation/ 与 demo/。自动测试、局部 CAD 回放和模型整轮结果分别记录；静态核验通过不代表与原 AD 一致或实物验证完成。
