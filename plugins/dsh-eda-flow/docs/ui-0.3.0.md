# 0.3.0 三栏流程与独立窗口

以用户确认的三栏设计稿为准，正式界面保留七步、21 个页签和两个辅助页面。显示板与空白设计使用同一套页面；显示板仅预填输入，不载入历史生成图片。

## 已接入的行为

- Harness 侧边栏的“电路设计”通过插件后台打开专用 Edge 应用窗口。再次点击聚焦已有窗口。聊天中没有浮层、遮罩、iframe 或全局键盘事件。
- 独立窗口仅绑定回环地址，使用本机会话认证；模型凭据仍由 Harness 管理。顶部名称来自 Harness 当前模型选择，页面加载、保存和人工确认不发起模型请求。
- 第一步保存人工确认快照。其他阶段通过真实 `llm.prepareCall` 流接口读取资料、取得计划，再运行现有 KiCad 工具。
- AI 助手的对话按项目和步骤保存，建议采用后才写入输入；生成动作与聊天分离。
- 新建、切换、改名分开；同名项目显示时间和短编号。重试只追加记录；空目录重放是当前项目的内部运行，不增加项目选择项。
- 输入上游变化使下游结果待更新；不显示失效图纸或旧检查通过结论。
- 本机文件上传后保存到项目资料目录。原始工程、文本依据和 PDF 走真实提取；默认输入中缺少的原始 AD 文件仍标为来源记录。
- 原理图、PCB 正反面和 3D 图片来自当前有效生成文件，可放大和下载；实际检查及执行记录保留在对应阶段。
- 鉴权、明确额度错误、限流、超时、取消、输出截断、格式错误与工具错误分别记录。没有额度证据时不提示余额不足。

## 本机验证

- 14 个 Node 检查通过，包括真实 Harness 服务注册、模型流适配、人工确认、对话采用、身份稳定和独立窗口接口认证。
- Playwright 覆盖七步页面、两个辅助页、保存、确认、重试、刷新、上传、错误状态及五档窗口宽度。
- 模拟模型配合真实 KiCad 从输入生成显示板；28 类工程内容与基准一致。
- 在另一空目录重放已记录方案，28 类内容一致，重放模型请求为 0。
- 本轮付费模型请求为 0。模拟服务和测试响应仅在 `test/`，不进入安装包。

真实模型生成能力留给内网验证。本轮验证的是正式接口的响应处理、实际工具生成、结果一致性和可重放性。

## 文件

- `frontend/` 是已确认页面的维护源码；`client/` 是随包部署的构建产物。
- `src/window.js`、`scripts/open-window.ps1` 负责独立窗口。
- `src/ai.js` 使用 Harness 当前模型，`src/errors.js` 分类服务错误。
- `src/service.js` 保存项目、输入、确认、阶段结果和对话。
- `test/browser-three-column.py`、`test/three-column.test.js` 和 `test/integration-offline.mjs` 为本机验证入口。

工作目录中 `design-window-session.json` 是本机窗口连接记录，不要作为工程交付资料公开分享。
