# 原理图到 PCB

PCB 使用当前已经确认的原理图。补充封装不会改变器件值、信号网络或 NC；第六步生成一个绑定封装的原理图副本，并与原输入再次导出网表比对。原先的原理图文件保持可追溯。

## 输入

1. 在第六步启用 PCB，核对板框、铜层、可布线层、过孔限制、线宽间距和装配面。
2. 用“添加封装 PDF / DOCX”上传局部封装资料。第六步附件单独保存，不使已确认的电路步骤失效。
3. 资料必须能确定全部焊盘编号、类型、局部位置、形状尺寸、孔径、角度、层，以及布局占位范围。自定义铜形需要完整顶点，圆角焊盘需要圆角比。仅有封装名称或脚距不够。
4. 厂家资料、工程测量、用户机械图分别标注来源。测量所得的图形边界可用于保守占位，但不能称为厂家本体尺寸或公差验证。

当前新增导入工具支持提取后的五列焊盘表：编号、类型/形状、中心坐标、宽高/孔径、角度/层。模型选择表格、列和来源页；程序读取全部行与原始小数。程序不接受模型自填的焊盘坐标。支持圆、矩形、圆角矩形、椭圆和多边形铜形；不支持的表格或纯图像尺寸图会保留为缺项，不能声称任意规格书都能自动建库。

## 执行及输出

`pcb_import_footprint` 按器件分次读取当前附件。编号重复表示同一逻辑引脚的多个物理焊盘；无编号辅助焊盘不会变成新电气引脚。核对包括所有 NC 引脚。目前逻辑引脚号与封装号须相同，异号映射会明确拒绝。

生成的 `EvidencePkg.pretty` 封装库留在项目里，附有来源页、表格原行、尺寸、编号映射和文件指纹。库不含整板位置。原资料的纳米级铜形锚点若在边界上，会在 KiCad 中形成独立小岛；程序将这种非实体锚点移入铜形内部，同时反向平移局部顶点，使实际铜形顶点保持原位置，记录转换前后锚点与 1 nm 坐标精度。程序不扩宽铜形去填补连接。

布局先预留大器件的真实占地，并检查通孔/背面铜形对另一面的占用。普通器件按网络关系放置。若 DRC 仍有未连通项，程序从实际报告提取受阻网络，逐轮提高相关外围的放置优先级和距离权重；大器件仍按占地优先安排。较差候选不会覆盖最佳结果或污染后续反馈。最多七个候选，不保证任意单层电路都能自动布通；全部失败时保留最佳候选及真实 DRC。

普通器件不需要固定坐标；只有用户输入已明确给出的机械基准才能形成固定位置。布局会尝试多个器件间隔，不改变电路来使布线通过。生成失败或 DRC 有错误、未连接、原理图一致性错误时，第六步不能确认。

产物包括可编辑 PCB、绑定封装的原理图副本、封装库、`PCB-BOM.csv`、逐物理焊盘 `PCB-pad-map.csv`、来源记录、正反面图、布线日志、各候选 DRC、最终 DRC。预览中的封装框显示资料占位范围，不是补画的厂家外观。查看实际未连接数和原理图一致性结果，不把“已生成文件”理解成验收通过。

本次工具链使用 KiCad 10、其配套 Python/pcbnew、Java 21 及随插件提供的 Freerouting 2.1.0。安装脚本可用 `-JavaPath` 指定 Java 可执行文件；不指定时从环境路径查找 `java`。无需把规格书或整板 CAD 塞进插件包。

## 验证边界

原理图一致性和 DRC 通过不等于与参考 AD 工程相同，也不证明器件采购、机械装配、制造工艺、温升、信号完整性或电源瞬态已经验证。缺少制造铜层数、金属化要求、厂家公差或结构基准时，这些项保留在交付说明中。当前仍有各阶段确认，未提供无人值守的一键全流程承诺。
