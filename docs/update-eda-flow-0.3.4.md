# 电路设计 0.3.4：内网资料读取检查与七步操作说明

本次针对“点击整理输入后，7 个 CSV 校验不一致，第一步也失效”。已用模拟 TSD 包装复现触发机制；尚未取得内网文件的读取诊断，不能直接断定内网原因是加密。

## 已修改

- 检测 CSV 等输入中的 `TSD-Header`，提示读取授权问题；不解密、不删除保护头，也不接受已变化的哈希。
- 每次生成前，在请求模型前比较 Harness/Node 与 KiCad Python 对默认资料的读取。第二步可点“检查资料读取”，查看或下载仅含元数据的诊断记录。
- 器件、连接、PCB 等资料变化从第二步阻止执行，保留未改变的第一步确认。任务或调整要求本身变化仍会撤销第一步确认。
- 来源资料、器件和 BOM 表格移除无作用的勾选框。工程师明确选择的“带待确认项继续草稿”仍保留。
- 每步显示“本步操作”和可展开的“需要补什么、在哪里补”，补充入口跳到相应页签或上传窗口。

## 更新安装

在原仓库目录执行：

```powershell
git pull --ff-only origin main
if ($LASTEXITCODE -ne 0) { throw '拉取失败，请先停止更新' }
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-eda-flow.ps1 -Profile desktop
if ($LASTEXITCODE -ne 0) { throw '更新失败，请保留报错' }
```

更新脚本自动备份原插件与配置，保留项目目录、模型、登录及窗口运行时，不强行退出 Harness。等当前任务结束，正常退出整个 Harness（若仍在系统托盘运行，从托盘退出），重开后从侧栏“电路设计”进入。只关闭设计子窗口可能保留旧后台。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-eda-flow.ps1 -Profile desktop
```

必须同时看到 `installedVersion: 0.3.4`、`runningVersion: 0.3.4`、`activation: active`。使用自定义 profile 或 DSH 数据目录时沿用原值；备份位于原 DSH 数据目录下的 `plugin-upgrade-backups`。

## 处理已经出错的项目

1. 打开原项目，不用重新输入需求或再建项目。
2. 进入第二步，点 **检查资料读取**，检查完成后点 **下载诊断记录**。
3. 显示 **TSD 保护格式**：至少一个进程读到了保护头。把诊断中的进程路径交给内网 IT，核对 Harness/Node 和配置的 KiCad Python 的读取授权；或在获准环境导出可读副本。
4. 显示 **两端读取不同**：Node/Python 的字节不同，但不一定是加密，也可能在检查期间文件变化。诊断记录保留两个结果，不能直接判为同一输入。
5. 显示 **内容校验不符**：两端读到的内容与发布包不同，未检测到 TSD 头；继续核查编码、换行、文件改写等原因。
6. 恢复可读且与原始资料一致的输入后，再点检查；通过后回到第二步重新“整理输入”。不能通过勾选“继续草稿”绕过资料完整性检查。

旧版已经撤销的确认不会被静默恢复。第一步若已经显示待更新，需核对默认任务后人工确认一次；0.3.4 不再因其他资料的 CSV 变化反复撤销该确认。

诊断无模型请求，不包含文件正文、账号或密钥；包含文件名、哈希、大小、格式特征和两个读取进程的路径。该记录不等于数据已解密或内网授权已修复。

## 显示板默认输入怎么走

| 步骤 | 默认已有 | 点击顺序 | 缺项在哪里补 |
| --- | --- | --- | --- |
| 任务与约束 | 需求、约束、验收目标 | 核对三个页签 → 确认并继续；不用模型 | 对应需求、约束或验收字段 |
| 资料与提取 | 已提取的器件、连接、PCB 与依赖 | 整理输入 → 等完成 → 查看提取数据/资料关联 → 确认并继续 | 添加资料；文字依据填资料关联。无需勾选下方来源记录或上传 AD |
| 器件与规格书 | 器件和引脚属性，缺厂家 PDF | 读取并核对 → 参数复核 → 确认继续 | 规格书 → 添加规格书，绑定型号/位号 |
| 原理图 | 连接、符号、参数、页面坐标 | 生成原理图 → 图纸/检查 → 确认继续 | 连接与参数补充栏，或上传连接表等资料 |
| BOM 与封装 | 原物料属性、封装几何、引脚映射 | 生成并核对 → 物料表/封装映射/检查 → 确认继续 | 物料表补充栏；上传料号表或封装图纸 |
| PCB | 板框、布线、铜区及可用模型 | 生成 PCB → 正反面/3D/检查 → 确认继续 | 板框与层叠确认制造铜层及孔金属化；布局布线补充要求；上传机械图/模型 |
| 核验与交付 | 显示板目标及上游结果 | 运行核验 → 差异与待办 → 确认交付 → 下载工程；可另做空目录重放 | 差异项链接返回原步骤补充，再重新生成受影响结果 |

资料缺项可明确选择“带待确认项继续草稿”，仍记录为待复核。显示板缺少厂家 PDF、原 AD 编译网表/页面 PDF、数码管原始三维模型，制造事项也需确认。正式流程使用 Harness 当前模型；本机验证均为模拟响应加真实工具，不消耗额度。

- 使用已安装 0.3.4 的独立原生窗口，新建显示板项目并实际点击七步，全部确认后刷新仍保留；第一步结果哈希始终不变。
- 真实 KiCad/Python 生成原理图、BOM、PCB、预览和交付 ZIP；显示板基准的 28 类内容比较一致。使用 12 次模拟模型响应，真实模型请求为零；本轮未重新执行空目录重放。
- 本次交付仍按草稿确认，保留 6 项待办；最终 ERC 1 条警告、DRC 40 条警告。流程完成不代表制造评审通过。
- 安装包的 172 个文件与本机安装内容逐一一致。原配置、其他插件依赖声明和已有项目记录保持不变。没有强制重启正常 Harness；其旧后台需要正常退出后重开才切换新版。
