# 电路设计 0.4.3：识别说明文字后的完整 JSON 动作

针对第四步截图中的失败：模型先返回 `U1 defined (revision 2). Now batch...` 一类说明，随后返回未加 Markdown 代码块的 JSON 工具动作。0.4.2 的解析器只接受纯 JSON 或单个 JSON 代码块，因此即使内部 JSON 完整，也会要求模型修正格式；两次修正仍保留说明文字时就会停止。

0.4.3 增加对“普通说明文字 + 唯一完整 JSON 对象 + 普通说明文字”的识别。按字符串、转义和括号边界提取对象，再用严格 JSON 解析和原有动作校验处理。电路参数不改写，原始回复和消息来源信息继续保留。该格式不再额外请求模型修正。

仍拒绝多条动作、数组包裹、对象缺损、错误转义或对象外夹杂其他对象/数组/代码块。不会自动补括号、补字段，也不会执行模型脚本。模型截断仍按 0.4.2 的恢复规则处理。

## 更新与继续

下载并解压 [0.4.3 升级 ZIP](../output/packages/EDA_Flow_Update_0.4.3.zip)，在解压目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-eda-flow.ps1 -Profile desktop -PackageVersion 0.4.3
```

等当前任务结束后正常退出整个 Harness，再重新打开，核对页面和运行后台均为 **0.4.3**。原来的纯文字项目可直接重试第四步，已确认的前面步骤和输入保留。失败执行的记录与文件保留，新一次手动执行使用新目录。

更新自动备份，保留配置、登录、窗口运行时和原模型调用开关；不自动发起模型请求。仅预览界面时可加 `-DisableModelCalls`。0.3.x 的历史资料包项目仍保留为历史项目；验证纯文字流程时通过“新建项目 → 使用显示板输入”开始。
